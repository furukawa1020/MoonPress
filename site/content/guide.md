# GitHub Pagesで使う

[サイト管理を開く](manage.html)。投稿、固定ページ、メディア、サイト設定をここから開けます。編集には対象リポジトリの書き込み権限があるGitHubアカウントでログインします。

## 新規作成

1. [記事を書く](write.html)を開き、タイトルと本文を入力します。
2. 段落の種類・太字・斜体・箇条書き・リンクを選べます。「プレビュー」で読み手に表示される内容を確認します。
3. 下書きは使っているブラウザーに自動保存されます。「下書き」から以前の原稿を選べます。別の端末へ移す場合は、「記事の設定」からHTMLやMarkdownを書き出します。
4. 「共有リンク」でURLを作ると、受け取った人がブラウザーで全文を開けます。本文はURLに含まれ、サイトの投稿一覧には追加されません。

### 固定URLで公開する

1. [記事を書く](write.html)で原稿を確認して「固定URLで公開」を押します。公開先のURL名を指定する場合は「記事の設定」で入力します。
2. 開いた確認画面で、必要に応じて所有者のChatGPTアカウントでサインインします。サインイン後に原稿が表示されない場合は、編集画面の「固定URLで公開」をもう一度押してください。
3. URLと本文を確認して「公開を依頼する」を押します。受付後、公開ジョブが原稿を検証し、固定URLに配信します。投稿は記事一覧にも載ります。
4. 確認画面が「公開済みです」と表示したら「公開ページを開く」を押します。公開ジョブの待ち時間によっては反映まで数分以上かかります。

公開時にGitHubアカウントやトークンの入力は不要です。すでに使われているURL名は上書きできません。

### リポジトリに原稿を追加する

[サイト管理](manage.html)の「リポジトリから原稿を作る」を開き、GitHub Actionsで種類・タイトル・URL名・本文を入力します。本文の改行は `\n`、段落の区切りは `\n\n` と入力します。本文はUTF-8で16,000バイトまでです。公開候補として確認する場合は `ready` を選び、実行結果のSummaryからPRを作成します。

このプロジェクトのGitHubリポジトリは公開されています。機密の原稿はブラウザーの下書きに留めてください。

## 投稿一覧を検索

1. [サイト管理](manage.html#inventory)の「投稿・固定ページを検索」を開きます。
2. GitHub Actionsの「Run workflow」でブランチを `main` にし、種類、公開状態、検索語、タグ名、カテゴリー名を指定します。空欄の絞り込み条件は省略されます。日付の新しい順・古い順・タイトル順を選べます。
3. 実行結果の「Summary」に該当件数と最大50件が表示されます。残りを見る場合は、同じ条件でページ番号を変更します。「原稿」で検索時点の版を確認し、「編集」や「履歴」で現在の原稿を操作します。

標準では一覧に掲載する公開対象だけを表示します。下書き・予約・一覧非掲載を含める場合は、サマリーに情報を共有するチェック欄を選びます。公開リポジトリではサマリーを誰でも閲覧できます。予約日時は日本時間です。公開状態は検索時点の原稿に基づき、実際の反映は「Pages公開の結果」で確認できます。

## 編集、画像、公開

- 公開済みのページは、サイト管理の一覧にある「編集」から開きます。GitHubで新しい作業ブランチに保存し、PRを作成します。
- 画像は「メディア」の「画像・ファイルを追加」からGitHubにアップロードし、投稿でファイル名を指定します。公開用フォルダに入れた画像は公開対象です。
- PRの **Review Pages changes** のSummaryで、追加・更新・削除される公開ファイルと、変更した記事のプレビューを確認します。公開対象外の原稿には下書き・予約などの表示が付きます。記事はGitHubの表示形式で、既存の公開画像を表示します。
- PRをマージしたら、サイト管理の「Pages公開の結果」を開きます。ビルドが成功したら公開ページを確認します。

## クイック編集・一括変更

1. 管理画面の一覧で原稿名（例 `guide.md`）をコピーし、「クイック編集」を開きます。
2. 「Run workflow」で `edit` を選び、原稿名と変更する項目を入力します。空欄は現状のままです。抜粋を消すなら消去欄に `excerpt` と入力します。
3. 実行後のSummaryからPRを作成します。公開差分を確認してマージします。

原稿名をカンマで区切ると、分類や公開状態などを最大20件に適用できます。タイトルとURL名は1件ずつ変更します。公開一覧に載らない原稿は「投稿一覧」で探すか、「すべての原稿を開く」で名前を確認できます。URL名を変えたときは、公開差分で古いURLへの影響を確認してください。

- **複製**は `duplicate` を選び、原稿名、新しいタイトル、複製先のURL名を指定します。コピーは下書きになります。
- **復元**は一覧の「履歴」から戻したいコミットの40桁のSHAをコピーし、`restore` で原稿名とSHAを指定します。
- 一覧非掲載のページはURLから閲覧できます。

## 予約公開

1. 新規作成では本文を入力して「公開候補」を選び、既存原稿ではクイック編集を開きます。
2. 予約日時に日本時間の `2027-01-01 09:00` またはUTCの `2027-01-01T00:00:00Z` を入力します。原稿にはUTCで保存されます。日付欄は記事の表示日です。
3. PRをマージすると予約が有効になります。公開ジョブが定期的に予約を確認します。GitHub Actionsの待ち時間やPagesの反映時間により、公開が遅れる場合があります。
4. 予約を解除するにはクイック編集の消去欄に `publish_at` を指定します。公開候補の原稿はPRをマージした後の通常の公開処理で公開されます。下書きの原稿は公開対象へ変更するまで公開されません。

## ゴミ箱と下書き復元

1. [管理画面](manage.html)で「ゴミ箱」を開き、移動・下書き復元フォームへ進みます。
2. `trash`（ゴミ箱へ移す）か `untrash`（下書きへ戻す）を選びます。原稿名は一覧または「ゴミ箱の原稿を見る」で確認します。カンマ区切りで最大20件を指定できます。
3. 確認欄を選んで実行し、SummaryからPRを作成します。サイト内に残るリンクが壊れる場合は、先にリンクを修正します。
4. PRの公開差分を確認してマージします。戻した記事は下書きに入り、クイック編集フォームに同じ原稿名を指定すると、公開対象にできます。

ゴミ箱の原稿は公開サイトの生成対象から外れます。公開リポジトリでは保管した原稿や過去の履歴を閲覧できます。

## 分類を管理

[サイト管理の「分類」](manage.html#taxonomy)で、公開投稿のカテゴリー・タグと件数を確認できます。分類名から公開アーカイブが開きます。

「カテゴリー・タグを変更」を開き、「Run workflow」で `main` を選びます。`categories`（カテゴリー）か `tags`（タグ）を選び、対象の分類名をカンマで区切って入力します。大文字・小文字は区別します。

| 操作 | 入力するもの |
| --- | --- |
| `add`（追加） | 追加する分類名と原稿名。既存の分類は残ります。 |
| `remove`（削除） | 外す分類名と原稿名。全原稿から外す場合は原稿名を空欄にし、確認欄を選びます。 |
| `rename`（改名） | 現在の分類名1つと新しい名前。原稿名を空欄にし、確認欄を選びます。 |
| `merge`（統合） | まとめる分類名2つ以上と統合先の名前。原稿名を空欄にし、確認欄を選びます。 |

原稿は最大20件まで指定できます。全原稿への操作には、下書き・予約・固定ページも含まれます。名前にカンマが入る分類は、原稿の「編集」から変更してください。

実行後の「Summary」で変更件数を確認してPRを作成します。改名・統合でアーカイブのURLが変わる場合は、公開差分で旧URLへの影響を確認してからマージします。

## 公開画像を同じURLで差し替える

1. サイト管理の「メディア」で公開画像を探し、ファイル名と「差し替え用 SHA-256」を控えます。
2. 「差し替え候補をアップロード」で候補を `site/media-inbox` に追加し、**新しいブランチ**にコミットします。アップロード用ブランチは候補を置く場所です。
3. 「画像を差し替える」を開き、GitHub Actionsのブランチ選択は `main` にします。フォームに対象名、SHA-256、アップロード先のブランチ名、候補のファイル名を入力します。
4. 実行結果のSummaryから差し替えのPRを作ります。公開差分を確認してマージすると、記事が参照していた同じURLから新しい画像が表示されます。

PNG・JPEG・GIF・WebPに対応します。候補は公開画像と同じ形式で8 MiB以下にします。公開リポジトリのアップロード用ブランチは閲覧できます。

## メニューを編集

[サイト管理の「ナビゲーションメニュー」](manage.html#menu)で、現在の表示順・名前・リンク先を確認できます。「メニューを編集」を開き、GitHub Actionsの「Run workflow」で `main` を選びます。

| 操作 | 入力するもの |
| --- | --- |
| `add`（追加） | リンク先と表示名。位置を空欄にすると末尾に追加します。 |
| `edit`（変更） | 現在のリンク先と、変更後の表示名またはリンク先。空欄の項目は保持します。 |
| `remove`（削除） | 現在のリンク先。 |
| `move`（移動） | 現在のリンク先と、移動後の位置。先頭は1です。 |

サイト内はファイル名（例 `guide.html`）、外部サイトは `https://` のURLを指定します。最大12項目です。処理後にSummaryからPRを作成し、公開差分を確認します。マージとPagesの公開が済んだら、トップ・記事・固定ページで表示を確認できます。

独自のレイアウトでは、ヘッダーに `{{menu}}` を置くと同じメニューを表示します。

## URL転送とURL名の変更

投稿・固定ページのURL名を変更するときは、クイック編集で原稿1件と新しいURL名を指定し、「公開済みの旧URLから転送する」を選びます。URL名を消去して原稿名に戻すときも選べます。実行後のSummaryからPRを作成すると、原稿と転送設定を同時に確認できます。

[サイト管理の「URL転送」](manage.html#redirects)では登録済みの元URLと転送先を確認できます。「URL転送を編集」を開き、Run workflowで `main` を選びます。

| 操作 | 指定する項目 |
| --- | --- |
| `add`（追加） | 元のファイル名と転送先 |
| `update`（転送先変更） | 登録済みの元のファイル名と新しい転送先 |
| `remove`（削除） | 登録済みの元のファイル名 |

ファイル名は `old.html` や `guide.html` の形式で指定します。公開前のチェックで、存在しない転送先、循環、公開ページとの衝突を検出します。公開差分を確認してPRをマージし、Pagesの公開後に元のURLを開いて確認します。

GitHub Pagesには元のURLで転送用HTMLを配信します。このページを開くとブラウザーが最新の公開先へ移動します。

## 表示設定を変更

[サイト管理の「表示設定」](manage.html#reading)で、投稿一覧やRSSの現在の設定を確認します。「表示設定を変更」を開き、Run workflowで `main` を選びます。

- **表示件数**は投稿一覧とカテゴリー・タグのアーカイブで個別に指定します。1〜1000件から選び、分割を解除する場合は `all` を入力します。
- **一覧レイアウト**は `site/layouts/` にあるファイル名（例 `workshop.html`）を指定します。標準に戻す場合は `default` を指定します。
- **タグ索引**を有効にすると、分類を探せる `tags.html` が生成されます。
- **RSS**は有効・無効を切り替えられます。初めて有効にする場合はタイトルと説明が必要です。配信件数の上限を設定でき、`all` で解除できます。無効にすると、タイトル・説明・上限の設定も消去されます。

空欄や `keep` の項目は保持します。実行結果のSummaryからPRを作り、公開差分を確認してマージします。件数を変えると、分割されたページの数やURLが変わることがあります。

独自レイアウトでは、ヘッダーに `{{rss_link}}` を置くとRSS有効時に購読情報が出力されます。

## 自分のリポジトリで使う

このリポジトリの構成を引き継ぎ、`site/site.json` の `base_url` と `pages_admin.repository` を自分のサイトに合わせます。GitHub Pagesを `gh-pages` ブランチのルートから公開する設定にして、最初の Publish Pages を実行します。編集対象は `main` の `site/` です。

[GitHub Pagesの設定と検証](https://github.com/furukawa1020/MoonPress/blob/main/docs/deployment.md)
